# 시트 DB 빌더 — Apps Script 설치 안내

원본 Google 시트를 Drive 안의 DB 스프레드시트로 정규화·유지하는 Apps Script 웹앱임.
Notion은 속성 유형·보기 구조의 참고 모델로만 쓰였으며, 외부 서비스 연동은 없음.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `Code.gs` | 서버 로직: DB 생성, 고유 키 기준 Upsert, 서식·드롭다운, `_schema`·`_log` 기록, 트리거, 실패 알림 |
| `Index.html` | 웹앱 화면 7종 (대시보드 · DB 뷰 · 실행 이력 · 원본/저장 위치 · 속성 설계 · 자동화 규칙 · 사용자 관리) |
| `appsscript.json` | 권한 범위, 시간대, 웹앱 배포 설정 |

## 설치 절차 (최초 1회)

1. [script.google.com](https://script.google.com) → **새 프로젝트** → 프로젝트명 `시트 DB 빌더`
2. **프로젝트 설정(톱니바퀴)** → "편집기에서 appsscript.json 매니페스트 파일 표시" 체크
3. 편집기에서 아래 3개 파일 내용을 붙여넣음
   - `Code.gs` → 기본 `Code.gs`에 전체 교체
   - `appsscript.json` → 전체 교체
   - `+` → **HTML** → 이름 `Index` (확장자 없이) → `Index.html` 내용 붙여넣기
4. 상단 함수 선택에서 `authorize` 선택 → **실행** → 권한 승인 (Drive, Sheets, 트리거, 메일)
5. **배포 → 새 배포 → 유형: 웹앱**
   - 실행 사용자: **웹 앱에 액세스하는 사용자**
   - 액세스 권한: **모든 사용자** (실제 접근은 앱 안의 허용 목록으로 통제됨)
6. 발급된 웹앱 URL로 접속 — **최초 접속 계정이 관리자로 등록됨**

## 다중 계정

- 계정마다 **독립 작업 공간**: 각자 자기 드라이브의 원본시트를 연결해 자기 DB를 만듦. 설정·실행 이력·자동화 규칙도 계정별로 분리되며, 서로의 파일은 공유되지 않음
- **관리자**(최초 접속 계정)는 [사용자 관리]에서 사용 계정을 등록·삭제함. 각 계정의 연결·최근 실행 요약만 표시되고 데이터 내용은 보이지 않음
- 목록에서 삭제된 계정은 즉시 접근 차단되고, 그 계정의 자동 갱신 트리거는 다음 실행 시점에 스스로 해제됨
- 추가된 사용자는 첫 접속 때 Google 권한 승인(확인되지 않은 앱 → 고급 → 이동)이 한 번 필요함

## 사용 순서

1. **원본 · 저장 위치**: 원본 스프레드시트·탭·헤더 행 선택 → DB 파일명·저장 폴더 지정 → 설정 저장
2. **DB 속성 설계**: 유형 자동 추천 확인 → 제목 1개·고유 키 1개 지정 → 속성 저장
3. **자동화 규칙**: 실행 방식·충돌·삭제 처리·행 조건·알림 지정 → 규칙 저장 (트리거 자동 설치)
4. **대시보드**: "지금 DB 갱신" → 첫 실행 때 DB 파일이 지정 폴더에 생성됨

## 생성되는 DB 파일 구조

| 탭 | 내용 |
|---|---|
| `DB_<이름>` | 레코드 본문. 제목 1열 고정, 유형별 서식·드롭다운, 시스템 컬럼(`_row_key`, `_src_row`, `_synced_at`, `_hash`) |
| `_schema` | 속성명·유형·원본 컬럼·시트 구현·고유 키·설명. **설명 열은 직접 채우면 다음 실행에도 유지됨** |
| `_views` | 보기 정의(필터·정렬·그룹) 초기값. 팀 공통 조회 기준으로 편집해 사용 |
| `_people` | 사람 속성 드롭다운 원본. 이메일 열은 직접 입력 |
| `_archive` | 원본 삭제 또는 행 조건 제외 레코드 |
| `_log` · `_log_detail` | 실행 요약 · 행 단위 결과 (상세는 최근 5,000행 유지) |

## 동작 기준

- **고유 키 Upsert**: 키 기준으로 신규는 추가, 값이 바뀐 행만 갱신, 변경 없는 행은 건드리지 않음
- **키 비어 있음·중복**: 해당 행 건너뜀 → "실패"로 기록, 실패 알림 발송
- **값 변환 실패**(예: 날짜 칸의 `9/31`): 빈 값으로 넣고 "경고"로 기록
- **DB 직접 수정 감지**: `_hash`로 판정. "원본 우선"이면 덮어쓰고, "DB 수정분 보존"이면 해당 행 갱신을 건너뜀
- **속성 구성 변경**: 기존 레코드를 새 열 순서로 재배치 (제외한 속성의 값은 제거됨)
- **원본 편집 감지**: 편집 1분 뒤 1회 실행 (연속 편집은 묶어서 처리)
- **동시 실행 방지**: 계정별 잠금 — 같은 계정은 한 번에 하나만 실행, 다른 계정과는 병행 가능

## 유의사항

- DB 본문 탭은 매 실행마다 스크립트가 다시 씀. 본문에 직접 넣은 색상·메모는 유지를 보장하지 않으므로 별도 탭 또는 `_views`로 관리함
- Apps Script 1회 실행 한도(6분) 기준, 수만 행 이하 원본을 대상으로 설계함
- ChatGPT에서 Google Drive를 연결한 뒤 DB 파일을 선택하면 `_schema` 탭으로 속성 의미를 해석하고 본문 탭을 조회할 수 있음
