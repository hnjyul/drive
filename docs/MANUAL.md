# 사용자 매뉴얼 — 시트 DB 빌더 (drive.j2inlab.workers.dev)

원본 Google 시트를 Drive 안의 정규화된 DB 스프레드시트로 자동 변환·유지하는 시스템임.
접속 주소 하나로 끝남: **https://drive.j2inlab.workers.dev**

| 구성 요소 | 역할 |
|---|---|
| Cloudflare Worker | 고정 주소·라우팅 (루트 접속 → 시트 DB 빌더로 바로 연결). main 병합 시 Cloudflare Git 연동(Workers Builds)이 자동 배포 |
| Apps Script 웹앱 | 시트 DB 빌더 본체 (화면 7종 + 동기화 엔진). `apps-script/**` 변경 시 GitHub Actions(clasp)가 같은 주소로 자동 배포 |
| GitHub 저장소 `hnjyul/drive` | 코드 원본 + AI 자동개발 파이프라인 |

요금: API 종량 과금 없음 (Claude 구독 토큰 · Cloudflare 무료 티어 · Google 무료 한도).
단, AI 파이프라인 실행은 Claude 구독의 사용량 한도(5시간 윈도·주간 한도)를 로컬 Claude Code와
함께 소모하므로, 이슈를 한꺼번에 여러 건 돌리면 한동안 로컬 사용이 제한될 수 있음.

## 1. 접속과 계정

- **https://drive.j2inlab.workers.dev** 접속 → Google 로그인 → 시트 DB 빌더가 주소 유지된 채 열림
- **허용된 계정만** 사용 가능. 등록 안 된 계정은 "접근 권한 없음" 안내가 뜸 → 관리자에게 등록 요청
- **관리자** = 최초 접속 계정. 좌측 [사용자 관리] 메뉴(관리자에게만 보임)에서 계정을 등록·삭제함
- **새 계정 첫 접속 시 1회**: Google 권한 승인 필요 — "확인되지 않은 앱" 경고가 나오면
  `고급 → 이동 → 허용` 순서로 진행함
- **계정마다 독립 작업 공간**: 각자 자기 드라이브의 원본시트를 연결해 자기 DB를 만듦.
  설정·실행 이력·자동화 규칙도 계정별로 분리되며 서로의 파일은 공유되지 않음

### 화면이 비어 보일 때

Google 로그인·권한 승인 화면은 임베드 안에 뜰 수 없음(Google 정책).

1. 우하단 **"화면이 비어 있으면 여기로 열기"** 버튼으로 새 탭에서 로그인·승인 후, 다시 원래 주소로 접속함
2. 그래도 비면(아이폰 Safari 등 서드파티 쿠키 차단 브라우저): **https://drive.j2inlab.workers.dev/db?direct=1** 로 접속함 — 임베드 없이 바로 이동하는 우회 경로

## 2. 처음 시작하기 — 3가지 방법

원본이 연결되지 않은 계정은 대시보드에 빠른 시작 안내가 뜸. [원본 · 저장 위치] 화면 상단에도 항상 있음.

### A. 샘플로 시작 (전체 흐름 체험, 추천)
1. **[샘플로 시작]** 클릭 → 예시 데이터 6건이 담긴 `[원본 샘플] 제안사업 관리대장`이 내 드라이브에 생성·연결됨
2. 자동으로 [DB 속성 설계] 화면으로 이동 → 자동 추천(고유 키·제목·유형)을 확인하고 **[속성 저장]**
3. 대시보드에서 **[지금 DB 갱신]** → `[DB] 제안사업 샘플` 파일이 생성되고 6건이 정규화되어 들어감

### B. 구조부터 설계 (노션식 — 구조를 먼저 정의)
1. **[구조부터 설계]** 클릭 → DB 이름과 속성(속성명·유형·고유 키 1개·제목 1개)을 정의
2. **[원본시트 생성 · 연결]** → 설계대로 서식이 잡힌 입력용 원본시트 `[원본] <이름>`이 생성·연결되고, 첫 갱신이 자동 실행되어 DB 뼈대가 만들어짐
3. 이후 데이터는 **원본시트에 입력**함 → 갱신 때마다 DB로 정규화됨

### C. 내 시트 연결 (이미 쓰는 시트가 있을 때)
1. [원본 · 저장 위치]: 원본 스프레드시트 → 시트 탭 → 헤더 행 번호 → DB 저장 위치(새 파일 권장) → **[설정 저장]**
2. [DB 속성 설계]: 유형 자동 추천 확인 → 제목 1개·고유 키 1개 지정 → **[속성 저장]**
3. [자동화 규칙]: 실행 방식 등 지정 → **[규칙 저장 · 트리거 설치]** → 대시보드에서 **[지금 DB 갱신]**

> 빠른 시작(샘플·구조부터 설계)은 DB를 항상 **새 파일로 시작**하므로 기존 DB 파일을 덮어쓰지 않음.
> 이미 연결된 원본이 있는 상태에서 빠른 시작을 누르면 교체 확인창이 뜸.
> 내 시트 연결에서는 "기존 DB 파일 사용"을 선택해 이전 DB에 이어서 반영할 수도 있음
> (이 경우 그 파일의 본문 탭이 갱신 때마다 다시 쓰임).

## 3. 화면별 안내 (메뉴 7종)

| 메뉴 | 용도 |
|---|---|
| **대시보드** | 파이프라인 상태(원본시트 → 변환 스크립트 → DB), [지금 DB 갱신], 최근 실행 결과, 최근 7일 반영 건수 차트 |
| **DB 뷰** | DB 레코드 조회 + 파일 구조(7개 탭) 설명, 시트 바로 열기 |
| **실행 이력** | 실행별 추가·갱신·보관·실패·경고 집계. 행을 누르면 행 단위 로그가 열리고, 실패·오류가 있는 실행은 [다시 실행] 가능 |
| **원본 · 저장 위치** | 원본시트·탭·헤더 행, DB 파일 위치 설정 + 빠른 시작 |
| **DB 속성 설계** | 원본 컬럼 → DB 속성 매핑. 유형 9종(제목·텍스트·숫자·선택·다중 선택·날짜·사람·체크박스·URL), 제목 1개·고유 키 1개 필수 |
| **자동화 규칙** | 실행 방식·충돌·삭제 처리·행 조건·알림 설정 |
| **사용자 관리** (관리자만) | 계정 등록·삭제 + 계정별 상태 요약(원본·DB·자동화·최근 실행) |

### 자동화 규칙 옵션

- **실행 방식**: 수동 / 시간 기반(15분·1시간·매일 지정 시각) / 원본 편집 감지(편집 1분 뒤 1회, 연속 편집은 묶음)
- **충돌 처리**: 원본 우선(기본) / DB 수정분 보존 — DB에서 직접 고친 행은 갱신하지 않음
- **삭제 처리**: 원본에서 사라진 행을 `_archive` 탭으로 보관(기본) / 진행상태를 "원본 삭제"로 표시 / DB에 그대로 둠.
  "원본 삭제" 표시 방식은 속성명이 정확히 **진행상태**(선택 또는 텍스트 유형)인 속성이 DB에 있어야 동작함 — 없으면 경고만 기록되고 행은 그대로 남음
- **행 조건**: 특정 조건의 행만 DB에 포함 (=, ≠, 포함, 비어 있음, 이후, 이전)
- **알림**: 실패·부분 실패 시 메일 / Teams 웹훅 발송

### 생성되는 DB 파일 구조

`DB_<이름>`(본문) · `_schema`(속성 정의 — GPT가 DB 의미를 해석하는 기준표) · `_views`(보기 정의) ·
`_people`(사람 드롭다운) · `_archive`(보관) · `_log`·`_log_detail`(실행 이력).
상세 동작 기준은 [apps-script/README.md](../apps-script/README.md) 참조.

## 4. 기능 추가·수정 요청 — AI 자동개발 파이프라인

새 기능이 필요하면 Claude Code 세션에서 **"이슈생성" + 요구사항**이라고 말하면 됨.

- 요구사항이 다듬어져 GitHub 이슈(`ai-feature` 라벨)로 등록되고, 이후는 전자동:
  **AI 구현 → 테스트·품질 게이트(최대 3회 시도, 실패 시 자동 수정 최대 2회) → 보안 스캔 → PR → AI 리뷰 → 자동 병합 → 자동 배포**
- 진행 상황은 이슈 코멘트로 확인함 — 구현이 끝나면 "자동 구현 완료(PR 링크)" 코멘트,
  병합되면 "✅ 자동 병합 완료" 코멘트가 달림. **⚠️ 코멘트만 조치가 필요한 실패 신호**임
- Claude Code 없이도 가능함 — GitHub에서 이슈를 만들고 본문에 요구사항을 적은 뒤
  `ai-feature` 라벨을 붙이면 동일하게 실행됨 (또는 Actions 탭 → AI Development Pipeline →
  Run workflow에 요구사항 입력. 단, 라벨 방식이어야 실패 시 ⚠️ 코멘트를 받음)
- 적용 범위: Worker 쪽(주소·라우팅·웹 기능)은 전자동. 시트 DB 빌더 본체(`apps-script/`)는
  세션에서 수정 후 push하면 clasp CI가 같은 주소로 자동 배포함 (수동 재배포 불필요)

## 5. 예약 경로 (Worker)

| 경로 | 동작 |
|---|---|
| `/` 및 그 외 모든 경로 | `/db`로 리다이렉트 |
| `/db` | 시트 DB 빌더 (주소 유지 임베드) |
| `/db?direct=1` | Apps Script 원 주소로 바로 이동 (우회 경로) |
| `/health` `/version` | 상태·버전 JSON |
| `/settings` | 시트 문서 ID 저장 화면 (메뉴 기능용 백엔드 — 유지) |
| `/menu` | 저장된 시트에서 메뉴 항목 JSON 반환 (현재 소비처 없음 — 향후 포털용으로 유지) |

> **주의**: 허용 계정 검사는 시트 DB 빌더(/db)에만 적용됨. `/settings`·`/menu`는 로그인 없이
> 누구나 접근할 수 있으므로, 공개해도 되는 시트 ID만 저장할 것.
>
> `/menu`를 나중에 활용하려면: ① 메뉴 시트를 "링크가 있는 모든 사용자 – 뷰어"로 공유
> (비공개면 빈 배열 반환) ② 첫 번째 탭에 1행 헤더 + A열 메뉴명·B열 경로·C열 순서(숫자)로 작성
> ③ `/settings`에는 시트 URL 전체가 아니라 **문서 ID**(주소의 `/d/`와 `/edit` 사이 문자열)만 입력

## 6. 문제 해결

| 증상 | 조치 |
|---|---|
| 화면이 비어 있음 | §1 "화면이 비어 보일 때" 절차 (폴백 버튼 → direct=1) |
| "접근 권한이 없습니다" | 관리자가 [사용자 관리]에서 해당 이메일 등록 |
| 실행 실패 | 대시보드 상단 오류 배너 확인 → [실행 이력]에서 행 단위 로그 확인 → 원인 수정 후 [다시 실행] |
| 갱신했는데 값이 안 바뀜 | 충돌 처리 "DB 수정분 보존"으로 두고 DB를 직접 고친 행일 수 있음 — 실행 이력에서 "보존" 여부 확인 |
| 자동 갱신이 안 돎 | [자동화 규칙]에서 트리거 상태 확인 후 재저장. 허용 목록에서 삭제됐던 계정의 트리거는 자동 해제됨 |
| 찾는 시트가 선택 목록에 없음 | 파일 목록은 **최근 수정순 80개**까지만 표시됨 — 그 시트를 한 번 열어 아무 셀이나 수정한 뒤 목록을 다시 불러옴. (DB 뷰는 500행, 행 단위 로그는 500건까지 표시 — 전체 데이터는 DB 파일과 `_log_detail` 탭에 온전히 있음) |
| 파이프라인 이슈에 ⚠️ 코멘트 | 코멘트의 실행 로그 링크 확인 → Claude Code 세션에 로그 전달하면 원인 분석·수정 |
| ⚠️로 끝났는데 PR이 열려 있음 | AI 리뷰가 거절했거나 이후 단계가 실패한 것 — PR의 리뷰 내용·체크 결과를 보고 직접 병합하거나 닫음 (방치하면 `ai/feature-N` 브랜치가 쌓임) |
| 병합·✅ 코멘트까지 떴는데 사이트 반영이 안 됨 | Worker 배포는 Cloudflare가 수행함 — Cloudflare 대시보드 → Workers & Pages → drive → 빌드 기록에서 실패 여부 확인 후 재시도 (이 실패는 GitHub에 알림이 오지 않음) |
